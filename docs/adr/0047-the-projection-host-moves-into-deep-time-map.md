# The projection host moves into deep-time-map, and the Python API ships beside it

`StoryMaps/shared/js/globe.js` is **710 lines of WebGL**: a projection host
offering orthographic, Spilhaus and Robinson, sampling an equirectangular
paleogeography texture, with the Robinson table transcribed once so the shader's
inverse and the JS-side forward projection cannot drift apart. With `geo.js` and
`robinsonSeams.js` it is about **1,250 lines**, and it contains **no
StoryMaps-specific references of any kind**.

deep-time-map's layers — `BoundarySeries`, `PointLayer`, `PolygonLayer`,
`VelocityField`, `hover`, `timeseries-panel` — draw *over* it as 2-D canvas
overlays. Neither half can render a page without the other.

So the generic renderer for this whole family currently lives in a **stories
repo**, and the library it depends on cannot draw anything on its own.

**Decision: `globe.js`, `geo.js` and `robinsonSeams.js` move into
deep-time-map. The Python API ships beside them in `deep-time-map/python/`.**

## Why there

deep-time-map's own README already claims this territory:

> Two halves that share one data contract: `python/` — export a time series from
> a GPlates reconstruction model into web-ready GeoJSON and JSON. `js/` —
> dependency-free ES modules that draw that data onto a 2D canvas.
> They live in one repo because the schema is the product.

The projection host is the missing piece of that claim, not an addition to it.
With it, the library is self-sufficient: export a reconstruction and draw it.
Without it, "draw that data" is only true if you also have a file from
somewhere else.

Both Geode and StoryMaps already vendor deep-time-map as a git submodule of
`github.com/siwill22/deep-time-map` (Geode pinned at v0.7.1, StoryMaps at
v0.6.0), so both acquire the renderer by advancing a pin. No new submodule, no
fourth repo.

## Rejected alternatives

**Leave `globe.js` in StoryMaps and have `geode` depend on it.** No migration
and no churn in seven working pages. Rejected because generated viewers would
then depend on a stories repo — making StoryMaps a library by accident, and
leaving Geode unable to use the renderer without vendoring its sibling. This is
the arrangement that produced the current split in the first place.

**A fourth repo for renderer + layers + Python.** Conceptually cleanest. Rejected
because it is a fourth submodule pin to keep in step for a boundary deep-time-map
already claims to own.

## What was actually moved (amended after building it)

deep-time-map v0.9.0 ships `js/raster-globe.js` and `js/camera.js`. Two deviations
from the decision above, both discovered by doing it:

**`robinsonSeams.js` did not move.** It depends on a vendored copy of d3-geo's
antimeridian clip, which lives in StoryMaps' own `vendor/` — moving it would drag a
third-party subtree into a library whose whole claim is that it has no dependencies.
Since this ADR was written, deep-time-map grew its own seam arithmetic
(`robinson.js`'s `meridianCrossing()`/`wrapLonDelta()`, v0.7.0), so the
library-native path for the same problem already exists. StoryMaps keeps its d3-based
splitter for the pages that use it.

**`geo.js` shrank rather than moved.** Roughly a third of it was already duplicated
in deep-time-map — the unit-vector helpers in `sphere.js`, the quaternions in
`rotations.js`, the published Robinson table in `robinson.js`. `camera.js` imports
those instead of carrying second copies, so what moved is only what a *camera* needs:
view matrices, Spilhaus, the pannable Robinson forward.

**The class is `RasterGlobe`, not `Globe`.** The barrel already exports
`Orthographic` and `Robinson` as projectors; a third thing called `Globe` sitting
beside them invited exactly the confusion the rename removes.

## Consequences

- **Seven StoryMaps pages re-point their imports.** A pure migration with no
  behaviour change, verifiable by screenshot diff — and worth doing as its own
  step before anything is built on top (see the staging in
  `docs/plans/python-first-viewer-api.md`). **Not yet done:** the igneous zircons
  viewer was built against the moved copy first, so the move is proven by a working
  consumer before seven working pages are touched.
- **deep-time-map grows a WebGL dependency.** Its README currently says
  "dependency-free ES modules" drawing "onto a 2D canvas"; both claims need
  amending. The layers stay canvas-2D; the host does not.
- **Geode's `viewer/src/` is unaffected and stays the answer for gridded
  Models.** Volumes, cutaways and isosurfaces cannot be drawn by this renderer at
  all. Geode's `generator/` (`ViewerRecipe`, `validateRecipe.mjs`) remains that
  other path. The two recipe vocabularies should converge eventually; forcing it
  now would block this on a refactor it does not need.
- Themes already live in deep-time-map (ADR-0039), so an Explorer generated by
  this API gets them for free rather than needing a parallel palette.
